# Milestone v1.1: Closing the limitations list

**Status:** ✅ SHIPPED 2026-08-11
**Phases:** 10–17 (plus the inserted 10.5)
**Total Plans:** 43 across 9 phases
**Releases:** Fly v4 → v12
**Audit:** [`v1.1-MILESTONE-AUDIT.md`](../v1.1-MILESTONE-AUDIT.md) — `tech_debt`, all three recommendations actioned

## Overview

The v1.0 README listed nine known limitations. This milestone took on **all nine** — including
the two the README called deliberate — and closed every one.

Six of the nine reverse a design position the project argues *for*, rather than fixing a defect.
That shaped the whole milestone: it **opens** by promoting the five load-bearing decisions to
numbered ADRs, so every later reversal supersedes a record instead of quietly contradicting a
paragraph. From there the work runs outward-in — infrastructure nothing else depends on first
(multi-machine Postgres, pooling), then identity and lifecycle, then data migration and cost,
then the measurement that makes quality changes visible, and only then the two reversals that
change what the pipeline *says*.

The register of expected reversals is now **spent**: ADR-0011 recorded the last one, and the
index's "remaining expected supersessions" sentence describes an empty set.

**One phase was inserted.** Phase 10.5 existed because mapping the codebase found a *live*
exposure the README never listed: the session read and delete routes had no auth dependency, and
`DEMO_TOKEN` did not close them. Confirmed against production by reading real sessions and
deleting two over plain `curl`, then fixed and shipped the same day.

### Phase 10.5: Close the live endpoint exposure (hotfix)
**Goal**: The public service stops handing session contents to anyone and stops accepting anonymous deletes
**Status**: ✅ Complete — shipped as Fly release **v4** on 2026-08-04. All four endpoints return 401 anonymously from the open internet; the demo still serves anonymous research runs.
**Depends on**: Nothing — ships ahead of Phase 11 regardless of Phase 10's state
**Requirements**: REQ-live-endpoint-exposure
**Success Criteria** (what must be TRUE):
  1. `GET /sessions`, `GET /sessions/{id}`, `GET /sessions/{id}/trace` and `DELETE /sessions/{id}` are no longer reachable without credentials on the deployed service. Today all four lack `Depends(guard)` (`src/research_agent/service.py:514`, `:519`, `:533`, `:539`).
  2. Setting `DEMO_TOKEN` actually protects them. It does not today: `check_token` runs only inside `guard`, and these four paths never reach it — so the existing token control is inert on exactly the endpoints that leak.
  3. `DELETE /sessions/{id}` is rate-limited, not merely authenticated. It is currently both unauthenticated and unmetered, which makes wiping the demo a two-line script.
  4. The SSE error handler redacts exception text (`src/research_agent/service.py:263`). The redaction helper already exists and is tested — the `/health` path uses it correctly; this call site just is not wired to it.
  5. Tests cover each newly-guarded path for both the 401/403 case and the authorised case, and fail if a future endpoint is added to the sessions router without a guard.
  6. Verified against the deployed service, not just locally: an unauthenticated `GET /sessions` from the open internet returns 401/403.

**Outcome (2026-08-04):** all six met, with SC-2 satisfied by a **superseding decision** rather than
literally. Research found that setting `DEMO_TOKEN` in production would 401 every anonymous visitor
on `POST /research/stream` and kill the public demo — `guard` already checks it and the demo page
sends no token header. SC-2's intent was "the token control stops being inert on the endpoints that
leak"; that is met by a separate `SESSIONS_TOKEN` (with `DEMO_TOKEN` accepted as a fallback value),
which fails closed at 403 when unset. `DEMO_TOKEN` must remain **unset** in production. Locked in
`10.5-CONTEXT.md` § Protection mechanism.

SC-5's structural test was nearly worthless as first conceived: fastapi 0.141.1 leaves an
`_IncludedRouter` in `app.routes`, so a flat walker sees only the two `@app.post` ask routes — both
legitimately guarded — computes an empty unguarded list, and reports a clean sessions tree while the
four leaking routes stay invisible. The shipped test walks recursively and asserts a route count
first. Two pre-existing tests had the same flat-scan bug and were fixed.

**Plans**: 5 plans

Plans:
- [x] 10.5-01-PLAN.md — Add the fail-closed `SESSIONS_TOKEN` credential to `limits.py`, with unit coverage
- [x] 10.5-02-PLAN.md — Regroup the four session routes behind it, rate-limit the DELETE, redact the SSE error, repair the suite
- [x] 10.5-03-PLAN.md — Behavioural coverage: refusal, service, fail-closed, fallback, unmetered reads, and a demo that survives
- [x] 10.5-04-PLAN.md — Recursive non-vacuous route-guard invariant, plus the DELETE's limiter pinned structurally
- [x] 10.5-05-PLAN.md — Truth up the docs, then the single cutover and live verification (checkpoint)

**Notes for discuss-phase:**

- Decide what `GET /sessions` should do long-term. Guarding it is the fast fix, but a public demo arguably should not have a global listing endpoint at all, even an authenticated one. That question belongs to Phase 12; this phase only has to stop it being open.

## Milestone Summary

**Decimal Phases:**

- **Phase 10.5: Close the live endpoint exposure (INSERTED)** — inserted after Phase 10 for a
  live security exposure found during codebase mapping, not present in the requirements list.
  Shipped as Fly release v4 the same day it was found.

**Key Decisions:**

| Decision | Rationale | Record |
|---|---|---|
| Promote five load-bearing decisions to ADRs *before* any reversal lands | Six requirements reverse a stated position; each must supersede a record, not contradict prose | Phase 10 → ADRs 0001–0005 |
| Session endpoints fail closed on their own token | The demo must stay anonymous while the operator's view does not | ADR-0006, later superseded by 0007 |
| Fairness keys on an auto-issued anonymous identity; the global cap bounds the bill | An auth wall heavy enough to stop a stranger destroys the demo's whole value | ADR-0007 supersedes 0006 |
| Embedding migration is two commands — copy, or re-embed | Re-embedding at cutover changes recall and infrastructure at once: two suspects, no way to separate them | ADR-0008 |
| Answer quality is graded from *recorded* runs, never claimed of the current model | A green suite that quietly implies "the model is good" is worse than no suite | ADR-0009 |
| The critic runs on a **more capable** model than the writer it gates | The user's own position, quoted verbatim in the record: "Use Opus as the critic's model since it has to be more capable than the writer's model" | ADR-0010 supersedes 0005 |
| Grounding means *sole source of truth*, not *no new search* | The old design conflated them; refusing to search was the enforcement, not the guarantee | ADR-0011 supersedes 0003 |
| The reservation is sized on measurement, not estimate | Two live runs put a typical run above the estimate; the docstring's own rule said to raise it | v1.1 audit W2 — $0.20 → $0.30 |

**Issues Resolved:**

- **A live security exposure**, found by mapping rather than by the requirements list: four
  session routes reachable by anyone, confirmed against production, closed in Fly v4.
- **A latent data-loss bug in `migrate.py`**, found while building the embedding migration.
- **The follow-up refusal text *was* the shipped answer** — discovered RED-first in Phase 17,
  critic-approved precisely because it claimed nothing. That measurement became ADR-0011's
  central argument.
- **`_execute` could lose a completed run from the ledger** — found by the milestone audit;
  the daily cap's only input was blind to that spend permanently.
- **Sixteen-plus vacuous gates across seven phases.** The recurring defect of the milestone,
  and the discipline compounded against it: waves routinely ran 10–15 mutation probes against
  plans naming three, and twice a probe *passed and the probe itself was wrong* and was
  re-targeted rather than banked.

**Issues Deferred:**

- The **full 40-case eval record run** (~$16.51 now, ~$21 after 2026-09-01). The machinery is
  proven end to end by one paid calibration case; recording the rest is an operator decision,
  and the deferral is explicit rather than an unstated gap.
- **`/health` checks that API keys are present, not that they work.** It stayed green through a
  full revoked-key outage in Phase 11. Now listed in the README's Limitations.
- **No CSP header on the demo page** (logged in Phase 12's deferred items).
- **The `DATABASE_URL` rollback path** is documented but was never exercised — running it would
  have churned production twice more.
- **Cookie invisibility to `document.cookie` and the JS reload path** were verified by mechanism
  (the header, a DOM shim) rather than in a real browser. Recorded rather than signed off.

**Technical Debt Incurred:**

- **No phase has a `VERIFICATION.md`.** Every phase ran plan → execute → PR without the verify
  step. The work *was* verified — validation contracts, gate batteries, mutation probes, live
  production checks, and the audit's own independent integration pass — but the artifact the
  framework expects does not exist, and the next person to run the audit hits the same wall.
  Writing nine after the fact would record a step that did not happen, so this stands open.
- **`run_finished` carries `run_id` but no `session_id`**, so a completed run is not addressable
  from the logs. It cost a wasted live run in Phase 17.
- **`/demo` publishes `reserved_run_usd` with no consumer reading it.**
- **`research_notes` grows per reaching follow-up** — bounded per turn, not per session.
- **The next reservation threshold is 2026-09-01**, when Sonnet 5's introductory window closes
  and a typical unchanged run rises roughly a third again. ~$0.40 covers it.
