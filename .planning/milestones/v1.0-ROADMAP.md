## Overview

v1.0 built a supervisor-routed research pipeline and operated it as a production service:
ask a question, watch it classify, search, draft, and fact-check its own draft against its
own research notes until every claim is grounded. The project's core value was fixed here
and never moved: **the pipeline never answers from model knowledge when it should be
answering from research — and it is demonstrable to a stranger in one click.**

The arc runs inward-out: the loop (1), what the loop remembers (2), how it converses and
fails (3), its HTTP surface (4), what it costs (5), how it is judged (6), how it ships
(7), where its state lives (8), and who can touch it (9). A housekeeping insertion (9.1)
repackaged the tree so the tests could not pass against code the image would not contain.

Two structural facts shaped everything after:

- **Routing was deterministic from the first commit** (DEC-01). Every later guarantee —
  the keyless test suite, the offline evals, the spend cap as a routing rule, v1.1's
  follow-up research bound — is downstream of control flow being a testable function of
  state rather than a model's choice.
- **The limitations list was written at ship time, deliberately.** Nine entries, "known,
  and deliberate for the scope," several argued *for* in the design docs. That register
  became v1.1's requirements wholesale — which is why six of v1.1's nine closures were
  recorded reversals of positions taken here, each superseding a numbered ADR.

## Phases

### Phase 1: Core loop
**Goal**: A question routes through a supervisor to workers and returns a grounded report
**Shipped in:** `5f20aa2` (2026-07-29, with Phase 2 — one commit, two phases)
Classifier → researcher → writer → critic under a supervisor whose routing table is a
chain of `if` statements over state (DEC-01); the critic a separate node with notes as
sole source of truth (DEC-02); bounded loops with `forced_stop_reason` (DEC-03); per-node
inference settings (DEC-05); a trace (DEC-06); a REPL.
→ [record](v1.0-phases/01-core-loop/01-SUMMARY.md)

### Phase 2: Memory
**Goal**: Notes persist and are recalled by similarity, not by growing the prompt
**Shipped in:** `5f20aa2` (2026-07-29)
Voyage embeddings, cosine recall above a `min_similarity` floor (DEC-07), JSON
persistence; memory as coverage-expander, not echo.
→ [record](v1.0-phases/02-memory/02-SUMMARY.md)

### Phase 3: Conversation & resilience
**Goal**: Follow-ups work over prior notes; stores are pluggable; transient failures retry
**Shipped in:** `b517710` (2026-08-01)
The responder and follow-up mode through the same critic (DEC-04 — the half of it that
refused to search was v1.1's sharpest reversal); the `MemoryStore`/`Embedder` seams with
three backends (DEC-08); node-boundary retries with jittered backoff (DEC-17); **the
project's first test suite** — 886 lines, keyless.
→ [record](v1.0-phases/03-conversation-and-resilience/03-SUMMARY.md)

### Phase 4: Service
**Goal**: The pipeline is reachable over HTTP, blocking or streaming, with durable sessions
**Shipped in:** `22e4607` (2026-08-01)
FastAPI over the same graph; sessions in SQLite, deliberately not LangGraph's checkpointer
(DEC-14); exactly one terminal SSE event (DEC-19); `service.py` holds no routing logic.
Also v1.0's costliest omission: the session routes shipped unauthenticated — found live
and closed in v1.1 as Phase 10.5.
→ [record](v1.0-phases/04-service/04-SUMMARY.md)

### Phase 5: Cost & observability
**Goal**: Every run reports what it cost, and a spend cap stops runaway runs
**Shipped in:** `b42c9c9` (2026-08-01)
Effective-dated prices with `pricing_unknown` failing loud (DEC-12); the spend cap as one
more routing row (DEC-11); failed runs kept in the denominator, `null` over fake zeros
(DEC-13); JSON logs; `/metrics`.
→ [record](v1.0-phases/05-cost-and-observability/05-SUMMARY.md)

### Phase 6: Evals
**Goal**: The pipeline's behaviour is checkable against a golden set
**Shipped in:** `b118e57` (2026-08-01)
Twelve authored cases driving the real compiled graph keylessly (DEC-20, caveat printed
every run); deterministic graders plus a structured-verdict Opus 5 judge (DEC-22). Found
the unreachable revision cap on its first run — each cap correct in isolation, the
composition wrong (DEC-21).
→ [record](v1.0-phases/06-evals/06-SUMMARY.md)

### Phase 7: Ship it
**Goal**: The service builds to an image, passes CI gates, and deploys
**Shipped in:** `b6d8649` (2026-08-01)
Two-stage non-root healthchecked image; CI running lint, tests, evals, image build, and a
container smoke test — every gate with `ANTHROPIC_API_KEY=""`, an invariant that never
moved again.
→ [record](v1.0-phases/07-ship-it/07-SUMMARY.md)

### Phase 8: Stateless
**Goal**: Sessions, metrics, and notes can live in Postgres/pgvector behind the same interfaces
**Shipped in:** `0741c61` (2026-08-01), plus the same-night deploy shakeout (`ee10cb8` →

(DEC-09); the cross-backend contract suite with the byte-identical metrics assertion

war stories — the `Decimal` that would have 500'd `/metrics`, the boot deadlock, the
silent `internal_port` merge.
→ [record](v1.0-phases/08-stateless/08-SUMMARY.md)

### Phase 9: Demo & guardrails

**Shipped in:** `9568ec5` (2026-08-02)

## Milestone Summary

**Key decisions** (all recorded as narrative rationale in `docs/DESIGN.md`; promoted to
numbered ADRs or superseded in v1.1 — see `.planning/intel/decisions.md` for the full 23):

| Decision | Rationale | Fate |
|---|---|---|
| Routing is a deterministic Python state machine | Testable with no keys, identical every run | ADR-0001, never reversed |
| The critic is a separate node, notes as sole source of truth | Self-assessment "reliably produces 'looks good to me'" | ADR-0002, never reversed |
| Follow-ups reuse the critic; no prior notes → refuse | Refusing beats answering from parametric knowledge | ADR-0003 — **reversed** by ADR-0011 (Phase 17): research one pass instead |
| Sessions in SQLite, not the checkpointer | Different feature, different failure model | ADR-0004, never reversed |
| Judge on a stronger model than the pipeline | The critic shared the writer's model then | ADR-0005 — **superseded** by ADR-0010 when Phase 16 removed the premise |
| Spend cap as a routing rule | Same table, same forced-stop machinery | Never reversed; extended twice |
| Effective-dated prices, fail-loud unknowns | A cost control that fails open is worse than none | Never reversed; extended by Phase 14 |
| One `DATABASE_URL` for all three stores | The real failure is setting one flag and forgetting another | Never reversed |
| Guardrails, not identity, for the public demo | Bounding spend judged sufficient for the scope | **Reversed** by Phase 12 (ADR-0007): anonymous auto-issued identity |

**Issues resolved during the milestone:**

- The **unreachable revision cap** — found by the evals on their first run; the backstop
  now derives from the cap it backstops (DEC-21).
- The **`Decimal` serialisation trap** — caught by the byte-identical cross-backend
  metrics assertion before it could 500 `/metrics` in production.
- The **boot deadlock** — eager DDL against a provider that pauses idle instances;
  resolved by lazy construction and the liveness/readiness split (DEC-18).
- The **silent `internal_port` merge** — Fly's auto-config PRs documented as never-merge.

**What v1.0 left open, on purpose:** the nine-item limitations register (see
[`v1.0-REQUIREMENTS.md`](v1.0-REQUIREMENTS.md)) — plus one exposure nobody knew about
(the unauthenticated session routes) and one untested path (`migrate_to_postgres.py`),
both surfaced and closed in v1.1.
