<objective>
Provision the Supabase database and flip production onto it — while the volume is still mounted, so
every step here is reversible.

Purpose: SC-1. This is the first half of the cutover, and its defining property is that nothing it
does is a point of no return. `fly secrets unset DATABASE_URL` restores the previous behaviour
entirely, because the SQLite data is still sitting on the volume underneath, merely unused.

Output: a live service whose three stores are Postgres-backed, plus the measured Fly→Supabase
latency the phase's `/health` budget depends on.

**Ordering is load-bearing.** The mount and the machine count do NOT change in this plan. They
change in 11-05, only after `/health` here has proven the database reachable — a machine with
neither a volume nor a reachable database is a broken machine.

**Deploys are manual**, and `enforce_admins` is `false` on `main`, so a direct push bypasses the two
required checks and records a bypass notice rather than being blocked. Land the code from plans
11-01 through 11-03 via a **pull request**, not a push.
</objective>

  <name>Task 1: Provision Supabase and set DATABASE_URL as a Fly secret</name>
  <read_first>
    - `docs/OPERATIONS.md` § Going stateless — as rewritten by plan 11-03; this task executes what it documents
    - `.planning/phases/11-multi-machine-state-and-pooled-postgres/11-RESEARCH.md` § Provider Decision, § Cutover Sequence steps 1-4, § Pitfall 4
  </read_first>
  <what-built>
    Nothing yet — this step has no CLI path. Supabase project creation is dashboard-only, and the
    **region cannot be changed after creation**, so it is the one choice worth double-checking before
    clicking.
  </what-built>
  <how-to-verify>
    1. Create a Supabase project in region **Oceania (Sydney) `ap-southeast-2`**. Not `us-east-1`,
       not the dashboard's default — the app runs in Fly `syd` and every `/health` probe pays the
       distance.
    2. Enable the `vector` extension: Dashboard → Database → Extensions → `vector`. Without it the
       notes store cannot create its table. Supabase installs it into the `extensions` schema, which
       is why `db.py` sets `search_path` on every pooled connection.
    3. Copy the **Session mode** pooler connection string — Project Settings → Database → Connection
       string → Session mode. The host looks like
       `aws-<n>-ap-southeast-2.pooler.supabase.com:5432` and the username looks like
       `postgres.<project-ref>`. Do **not** take the direct endpoint (`db.<ref>.supabase.co`) — it is
       IPv6-only on the free tier. Do **not** take the transaction-mode port `6543` — that mode is
       for transient serverless clients and breaks session semantics.
    4. Append `?sslmode=require` to the string if it is not already there. libpq's default is
       `prefer`, which silently accepts a plaintext connection, and `db.py` passes the DSN through
       untouched — nothing in the code will add it for you.
    5. Set it:
       `fly secrets set -a research-agent DATABASE_URL='postgresql://postgres.<ref>:<pw>@aws-<n>-ap-southeast-2.pooler.supabase.com:5432/postgres?sslmode=require'`
       Always pass `-a` explicitly. **This triggers a deploy** — machines restart and all three
       backends flip to Postgres on the next boot.
    6. Confirm the secret is registered without revealing it: `fly secrets list -a research-agent`
       shows a `DATABASE_URL` row with a digest.
    7. Confirm the release: `fly releases -a research-agent` shows a new version.

    Paste back into this session: the region you chose, the host shape (redact the project ref and
    password), and the `fly secrets list` output.
  </how-to-verify>
  <acceptance_criteria>
    - `fly secrets list -a research-agent` includes a `DATABASE_URL` row
    - The DSN host ends in `.pooler.supabase.com` and the port is `5432`, not `6543`
    - The DSN contains `sslmode=require`
    - The Supabase project region is `ap-southeast-2`
    - The `vector` extension is listed as enabled in the Supabase dashboard
    - `fly volumes list -a research-agent` still shows `agent_data` attached — nothing about the volume changed
    - No DSN, password or project ref is written to any file in the repository
  </acceptance_criteria>
  <resume-signal>Paste the region, the redacted host, and the `fly secrets list` output, then type "provisioned"</resume-signal>

    5. Measure the round trip from inside a machine, using the snippet in RESEARCH § Code Examples:
       `fly ssh console -a research-agent -C "python - <<'PY' ... PY"` printing connect+TLS ms and

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator clipboard → Fly secret store | The DSN with its password transits a terminal and a shell history |
| Fly machine → Supabase pooler | Credentials and every statement cross the public internet between two providers |
| Supabase project → the public internet | A free-tier Postgres reachable from anywhere, holding demo data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-14 | Information disclosure | DSN in shell history / a committed file | mitigate | Set only via `fly secrets set`; never written to `fly.toml`, `.env` or any planning doc. Plan 11-03's guard asserts `DATABASE_URL` is absent from `fly.toml`'s `[env]`. Redact the project ref and password in every pasted output |
| T-11-15 | Information disclosure | plaintext transport | mitigate | `sslmode=require` in the DSN, verified in Task 1's acceptance criteria. libpq defaults to `prefer`, which fails silently — hence an explicit check rather than an assumption |
| T-11-16 | Information disclosure | credentials leaking through `/health` | mitigate | `_describe_dsn()` strips the netloc password; Task 2 asserts no password appears in the body. Note the new DSN shape puts the project ref in the *username* (`postgres.<ref>`), which `urlparse().hostname` discards |
| T-11-17 | Denial of service | connection exhaustion on a 60-connection Nano | mitigate | `max_size` 5 on one machine here; `pg_stat_activity` checked before 11-05 doubles the fleet |
| T-11-18 | Spoofing | anyone reaching the public Supabase endpoint | accept | Free tier has no IP allowlist; the credential is the control, and it lives only in Fly's secret store. Bounded blast radius: demo data, no PII, and Phase 12 owns store lifecycle |
| T-11-19 | Elevation of privilege | direct push to `main` bypassing required checks | mitigate | `enforce_admins` is `false`, so land 11-01..11-03 via a pull request; the checks gate PRs, not every path to `main` |
</threat_model>
