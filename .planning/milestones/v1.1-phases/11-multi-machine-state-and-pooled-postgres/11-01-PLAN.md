<objective>
Replace the single lock-guarded Postgres connection in `db.py` with one process-wide
`psycopg_pool.ConnectionPool` per DSN, shared by all three stores.

Purpose: REQ-connection-pool. The reversal is justified by the machine count rising —
`fly.toml` sets `hard_limit = 16`, and two machines means **up to 32 in-flight requests
against one database**. Before this phase those 32 requests would have queued behind a single
serialised connection across a ~5 ms network hop instead of a local socket. That is the link
between the pool and the concurrency change, and it belongs in the module docstring verbatim.

Output: a pooled `db.py`, `psycopg-pool==3.3.1` pinned, and `tests/test_db.py` — a module that
does not exist today, even though `db.py` is the phase's main risk surface.

**No store needs editing.** `sessions.py`, `metrics.py` and `memory.py` each do
`self.db = database or db.Database(dsn)` and then `ensure_schema(...)`; none of them touch
`_conn` or `_lock`. The blast radius of this plan is one production module.
</objective>

  <read_first>

  <action>
    Reimplement `Database.cursor()` on the pool. `psycopg_pool.PoolTimeout` and `PoolClosed` both
    **subclass `psycopg.OperationalError`** — verified in `psycopg_pool/errors.py`. The existing
    `except (OperationalError, InterfaceError)` arm would therefore catch a checkout timeout and
    retry it, doubling the worst-case wait on an unreachable database. Catch
    `(PoolTimeout, PoolClosed)` **first** and re-raise immediately: the wait has already happened,
    and a second one buys nothing.

    Keep the two properties the current code has and the stores rely on: the retry is limited to
    exactly **one** attempt, and to connection errors only, so a genuine SQL error surfaces rather
    than running twice; and a non-database exception raised inside the `with` body — `KeyError` from
    `sessions.append_turn` is the live example — still propagates untouched.

    **`_apply_schema()` — the advisory lock must live on ONE connection.** `pg_advisory_lock` is
    *session*-scoped, which under a pool means *per checked-out connection*. Every call to
    `self.cursor()` is a separate `pool.connection()` checkout, so a shape that takes the lock in one
    `cursor()` block, runs the DDL in a second and unlocks in a third serialises nothing at all: the
    unlock executes on a different connection, `pg_advisory_unlock` returns `false`, and the lock
    stays held on a connection that has been handed back to the pool. With `max_size=5` that is the
    likely outcome, not the unlucky one — a leaked lock plus a race, from code that greps clean.

    So: open **one** `with self.cursor() as cur:` block and do all three inside it —
    `cur.execute("SELECT pg_advisory_lock(%s)", (SCHEMA_LOCK_KEY,))`, then `cur.execute(self._schema_sql)`
    inside a `try`, then in the `finally`
    `cur.execute("SELECT pg_advisory_unlock(%s)", (SCHEMA_LOCK_KEY,))` **and read its result**:
    it returns a boolean, and `False` means the lock was never held on this connection, i.e. the
    single-connection invariant has been broken. Raise on `False` rather than swallowing it, with a
    message naming the invariant — `ensure_schema` suppresses it, so a broken invariant costs a
    deferred retry rather than a crash, but it is no longer silent. Add a comment stating the
    invariant in one sentence so a later refactor that splits the block reads as the regression it is.

    Add a module constant `SCHEMA_LOCK_KEY = 3895545195` with a comment naming its origin
    (`zlib.crc32(b"research_agent.schema")`) — one key for all three schema blocks, so they
    serialise against each other too, not one key per store. Use the session-level pair, **not**
    `pg_advisory_xact_lock`: under `autocommit=True` there is no transaction to hang the lock on.

    Why this is needed now and was not before: `CREATE TABLE / INDEX / EXTENSION IF NOT EXISTS` is
    not atomic against a concurrent creator. This is the first phase in which two processes ever run
    the lazy schema path simultaneously against an *empty* database — which `fly deploy` across two
    machines and a start-clean database together guarantee. Belt and braces: treat
    `psycopg.errors.DuplicateTable`, `DuplicateObject` and `UniqueViolation` raised by the DDL block
    as "already applied" rather than as failure. Note in the comment that this tolerance is exactly
    why a string-only gate on `pg_advisory_lock` cannot prove the lock works — the real gate is the
    two-connection exclusivity test in plan 11-02 Task 3.

    `ensure_schema`'s contract does not change: it registers the SQL, tries once, and suppresses
    every exception. `_apply_schema` stays idempotent and retried on first use. **No DDL runs at
    construction time** — SC-4 stays true.

    Extend `tests/test_db.py`:
      - An **autouse fixture** in `tests/test_db.py` that calls `db.close_all_pools()` after every
        test. Without it the per-DSN registry makes the env-driven timing tests order-dependent:
        `_pool_for(dsn)` caches a pool built from `pool_timeout()` as read *at construction*, so a
        pool left registered by an earlier test at the 2.0 default would make a later test's
        `PG_POOL_TIMEOUT=0.5` assertion take ~2.0 s and fail. Refcounted `close()` self-cleans only
        if every test closes in a `finally`, which is convention rather than enforcement — the
        fixture is the enforcement. Each timing test must **also** use a DSN unique to itself.
      - The timing test: against a unique unreachable DSN with `PG_CONNECT_TIMEOUT=1` and
        `PG_POOL_TIMEOUT=0.5`, assert a `cursor()` call raises inside roughly one checkout timeout,
        not two — measure with `time.perf_counter()` and assert an upper bound below `2 ×` the
        configured timeout, so a reintroduced retry fails the test rather than merely slowing it.
      - Assert `issubclass(PoolTimeout, psycopg.OperationalError)` explicitly, so the test documents
        *why* the exclusion exists and starts failing if psycopg ever changes it.
      - Cover the retry-once path with a fake pool whose first `connection()` raises
        `OperationalError` and whose second succeeds, and assert a `ProgrammingError` is **not**
        retried.
      - A single-connection test using a fake pool that records which connection object each
        statement ran on: assert `pg_advisory_lock`, the schema SQL and `pg_advisory_unlock` were all
        executed against the **same** connection object, and that the fake handed out exactly one
