<objective>
Add the credential primitive this hotfix composes with: a `SESSIONS_TOKEN` env reader that
falls back to `DEMO_TOKEN`, and a FastAPI dependency that **fails closed** — 403 when nothing
is configured, 401 when the caller's header is absent or wrong.

Purpose: the defect being fixed is a control that existed in code and was inert in production.
`check_token` no-ops on an unset token, which is correct for the demo write path and fatal for
the session tree. This plan builds the separable, fail-closed variant and pins its behaviour
before anything is wired to it.

Output: `limits.sessions_token()`, `limits.require_sessions_token()`, corrected module
docstring, and unit tests in `tests/test_limits.py`.
</objective>

    Add two module-level functions to `src/research_agent/limits.py`, placed immediately after
    `check_token` so the contrast between them is readable.

    `sessions_token() -> str` — reads `os.environ.get("SESSIONS_TOKEN", "").strip()` and falls
    back to `demo_token()` when that is empty. Per-call read, not a module constant, because
    `tests/test_service.py` flips it with `monkeypatch.setenv`. Named for what it returns, per
    convention. Its docstring must state why the variable is separate from `DEMO_TOKEN`: the
    demo page sends no auth header, so setting `DEMO_TOKEN` in production would 401 every
    anonymous visitor on `POST /research/stream` and kill the demo; `SESSIONS_TOKEN` closes the
    session tree without touching the demo, and the `DEMO_TOKEN` fallback is what makes
    "setting DEMO_TOKEN protects the session endpoints" true rather than silently false
    (SC-2, per CONTEXT § Protection mechanism).

    `require_sessions_token(request: Request) -> None` — the FastAPI dependency.
      - `token = sessions_token()`; if falsy, `raise HTTPException(403, "Session endpoints are
        closed: no SESSIONS_TOKEN is set.")`. This is the fail-closed divergence from
        `check_token` and is CONTEXT § Failure default — do not return early.
      - Otherwise read `supplied = request.headers.get("x-demo-token", "")`. Reuse the
        `x-demo-token` header name; do not invent `x-sessions-token` (CONTEXT: Claude's
        discretion, resolved this way for one client-side story).
      - If `not supplied or not hmac.compare_digest(supplied, token)`, raise
        `HTTPException(401, "A valid X-Demo-Token header is required.")`. Use
        `hmac.compare_digest`, never `==`.
      - Positional `HTTPException(status, message)`, per convention.
      - Its docstring must record why it does not reuse `check_token`: carrying
        open-when-unset here is exactly what left every stored report world-readable on the
        deployed service — the control was present in the code and inert in production.

    Then correct the two now-false statements in the module docstring (lines 1-27):
      - The `DEMO_TOKEN` bullet (~lines 8-11) currently says only write endpoints need the
        header. Add a `SESSIONS_TOKEN` entry to the same indented tunables block describing it
        as the credential for the session read/delete tree, fail-closed, with `DEMO_TOKEN` as
        a fallback. The docstring may — and probably should — name `/sessions` in this new,
        accurate wording; what must disappear is the *claim* corrected in the next bullet, not
        every mention of the path.
      - The closing paragraph (~lines 24-26) says "Read-only endpoints (/health, /metrics,
        /sessions, the demo page) are never gated". Remove `/sessions` from that list and draw
        the distinction the change creates: *ops* reads (`/health`, `/metrics`, `/pricing`,
        `/memory`, the demo page) stay open because they cost nothing and are how you diagnose
        a refusing service; *session* reads return other people's research and do not.

    Do not touch `check_token`, `enforce`, or `status()`. Do not add a `sessions_token_required`
    field to `status()` (RESEARCH Q4: the demo page has no use for it).
  </action>
