# Phase 12 — UI Design Contract

> Visual and interaction contract for the demo page's identity-aware evolution.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope statement:** This is an evolution of `src/research_agent/static/index.html`
— one self-contained file, no build step, no framework, strict-CSP-compatible
(no external resources, no inline event handlers beyond the existing script
block idiom). Nothing in this spec may be implemented as a framework component,
an external stylesheet, or a CDN dependency. Every new DOM node is built with
the page's existing `el()` helper and `textContent` — **no `innerHTML`, ever**
(session task text is untrusted input, same rule as report markdown).

**The binding constraint (ROADMAP criterion 6):** a stranger following a résumé
link reaches a working demo with zero added friction. The identity is minted
silently. On a first visit with clean storage, the page must look and behave
**identically to today's page** except for one muted footer sentence. Any
visible step, prompt, banner, or modal before the first question is a FAIL.

## Spacing Scale

The page uses a rem-based scale (1rem = 16px). Declared values for new elements:

| Token | Value | Usage |
|-------|-------|-------|
| xs | .25rem (4px) | Inline padding inside badges, tight row padding |
| sm | .5rem (8px) | Gaps between row elements (matches form/badges gap) |
| md | 1rem (16px) | Default element spacing |
| lg | 1.5rem (24px) | Section margins (matches form/card margins) |
| 3xl | 3rem (48px) | Page-level breaks (matches `.wrap` top padding, footer margin) |

Exceptions (pre-existing, retained, do not "fix"): input/button padding
`.7rem .85rem`, card padding `1.4rem 1.5rem`, stage row padding `.3rem 0`.
New elements reuse these exact values where they play the same role.

## What Phase 12 Adds to the Page

Three additions, in order of visual weight. Total textual delta on a
cleared-storage first visit: **exactly two** — (1) the footer identity sentence,
and (2) the reworded `#limits` line ("for this browser" / "by all visitors",
required by AC10 per the locked fairness-ceiling decision — honest copy, not
ceremony). Neither adds an interactive step, prompt, banner, or blocking state.
Everything else appears only when the caller has history.

### 1. "Your recent research" — owned session list

**Placement:** between the `.limits` line and `#out`. New container
`<details id="mine">`, **not appended to the DOM at all until populated** (this
makes AC1's diff-against-baseline check cleanest — an empty container in the DOM
would itself be a first-visit delta).

**Markup idiom:** native `<details>`/`<summary>` — collapsed by default, zero
JS for the toggle, matches the no-framework posture.

```
<details id="mine">                     ← margin: 0 0 1.5rem; only in DOM flow when non-empty
  <summary>Your recent research (3)</summary>   ← --muted, .9rem, cursor:pointer
  <button type="button" class="session-row">…</button>  ← one per session
</details>
```

**Session row spec** (a `<button type="button">` for free keyboard access —
styled as text, NOT as the accent button):

- `display:flex; width:100%; text-align:left; background:none; border:0;
  border-bottom:1px solid var(--line); padding:.5rem .25rem; gap:.6rem;
  font:inherit; font-size:.9rem; cursor:pointer; color:var(--fg);`
- Content, left to right:
  - Task text: first line of the session's question, single line,
    `overflow:hidden; text-overflow:ellipsis; white-space:nowrap; flex:1`.
    Inserted via `textContent` (untrusted input).
  - Age: relative, muted (`color:var(--muted)`), e.g. `2d ago`, `4h ago`,
    `just now`. `flex:none`.
- Hover/focus-visible: task text color becomes `var(--accent)`;
  `outline: 2px solid var(--accent); outline-offset:-1px` on focus-visible
  (matches the input's focus treatment).
- Last row: `border-bottom:0` is acceptable but not required.
- Maximum rows rendered: 10, newest first. No pagination — this is a demo.

**Data source:** `GET /sessions` (now returns only the caller's sessions,
carrying the identity token — see Transport Dependency). Fetched once on page
load and re-fetched after each completed run (same lifecycle as
`refreshLimits()` — call it `refreshSessions()`).

**States:**

| State | Behaviour |
|-------|-----------|
| Empty (fresh identity, zero sessions) | Render nothing. No empty-state card, no placeholder, no skeleton. The first-visit page is indistinguishable from today's except the footer sentence. |
| Loading | Render nothing until the response arrives. No spinner. |
| Populated | `<details>` appears, collapsed, summary shows count. |
| Fetch fails / 401 / any non-2xx | Render nothing, swallow silently — same posture as `refreshLimits()`'s `catch { /* the page works without it */ }`. The core demo must never depend on this feature. |
| A listed session expires or vanishes between listing and click | Handled at click time, below. |

### 2. Session resume — the interaction flow

Clicking a session row:

1. If `busy`, ignore the click (same guard as the form).
2. `fetch GET /sessions/{id}`. On success:
   - Clear nothing — append to `#out` like every other interaction (the page
     is an append-only transcript by design).
   - Render each stored turn in order, reusing the existing *idioms*, not
     `result()` verbatim: the existing `result()` (index.html:225–254)
     unconditionally fabricates `$0.0000` when `cost_usd` is absent, renders
     `undefined revision(s)`, and carries side effects (sets `session`,
     placeholder, clears input) that must fire once per resume, not once per
     stored turn. **Extract a side-effect-free card renderer with conditional
     badges** — a stage line `Question: {question}` (or `Follow-up:` for turns
     after the first), then a `.card` with the answer through `renderReport()`.
     Render whatever badges the payload supports (`approved`, cost, revisions);
     omit badges whose fields are absent — never fabricate.
   - Set `session = id`; set the input placeholder to the existing follow-up
     placeholder ("Follow up on that — answered from its notes, no new
     search"); collapse the `<details>` (`open = false`); focus the input.
   - Subsequent submissions go to `/sessions/{id}/ask/stream` — this is the
     existing follow-up path, unchanged.
3. On 403/404 (expired, or refused): show the existing error-card component
   with the expiry copy from the Copywriting Contract, remove that row from
   the list, do NOT set `session`.
4. On network failure: existing "Could not reach the service" error card.

### 3. Identity affordance + identity-aware limits

**Footer sentence** (the entire visible footprint of identity): one plain-text
line added inside `<footer>`, above the existing `.mono` link row, inheriting
footer styles (`--muted`, .82rem). Static text — always true, no JS needed.
Copy is in the Copywriting Contract. No icon, no link, no dismiss control.

**Limits line** (`#limits`, populated by `refreshLimits()`): when `/demo`
becomes identity-aware, the wording distinguishes the per-browser rate limit
from the global spend cap honestly — the locked decision says the global cap
is the backstop and the fairness ceiling is documented, not hidden. Exact
strings in the Copywriting Contract. Visual treatment unchanged (muted, .82rem).

**429 handling:** unchanged mechanism — the existing error card shows
`Request refused (HTTP 429)` with the server's `detail` passed through
verbatim. The server owns limit copy; the page does not paraphrase it. If the
server distinguishes "your hourly limit" from "the shared daily budget" in
`detail`, the page displays it as-is.

## Copywriting Contract

Voice: the page speaks plainly, in sentences, and is honest about mechanics
("Watch the critic push back", "The run may still have completed and been
billed"). New copy matches that register — no marketing, no exclamation marks,
no "Oops".

| Element | Copy |
|---------|------|
| Primary CTA | `Research` (unchanged) |
| Follow-up placeholder | `Follow up on that — answered from its notes, no new search` (unchanged, now also set on session resume) |
| Session list summary | `Your recent research (N)` |
| Session row age | `just now` / `{n}m ago` / `{n}h ago` / `{n}d ago` |
| Empty state | Nothing rendered. Deliberate: an empty-state message would be ceremony the first visitor pays for. |
| Footer identity line | `Your sessions and notes are private to this browser and expire after 7 days of inactivity.` |
| Limits line, identity-aware | `Shared demo — {n} requests/hour for this browser · ${x} of ${y} spent by all visitors in the last 24h` (keep `a demo token is required` branch as-is if `token_required` survives) |
| Expired/refused session (403/404 on resume) | Title: `That session has expired` · Detail: `Sessions are kept for 7 days after their last activity. Ask a new question to start fresh.` |
| Rate/cap 429 | Server `detail` verbatim inside the existing `Request refused (HTTP 429)` card (unchanged) |
| Destructive actions | None. No delete UI in this phase (CONTEXT: no account management UI). `DELETE /sessions/{id}` stays API-only. |

## Transport Dependency (flagged, not decided)

The identity token must ride on **every** call site the page makes — currently
`POST /research/stream`, `POST /sessions/{id}/ask/stream`, `GET /demo`, and now
`GET /sessions` + `GET /sessions/{id}`. Constraint for the phase researcher:

- The streaming paths use `fetch` with a hand-rolled SSE reader (not
  `EventSource`), so a header IS technically possible today — but a cookie
  rides free on every path including any future `EventSource` use, and
  requires zero changes at the five call sites.
- **The transport decision (signed cookie vs bearer-in-localStorage, signing,
  rotation) belongs to the phase researcher per CONTEXT "Claude's
  Discretion".** This spec's only demand: whatever is chosen, the page-side
  cost must be near-zero and must not add a visible step. If a header is
  chosen, every `fetch` call site gains it; if a cookie, none change.
- Minting must be silent and non-blocking: the first question must be
  submittable immediately on first paint. No "initializing identity" state
  may ever render.

## Acceptance Criteria (executor/auditor-verifiable)

1. **Criterion-6 guard:** with cleared storage/cookies, the rendered page
   differs from the pre-phase page by exactly TWO textual deltas — the footer
   identity sentence and the reworded `#limits` line (AC10) — and nothing
   else. No banner, prompt, modal, spinner, or consent step; no new
   interactive element reachable before the first question. The question form
   is usable immediately. (An auditor diffing the first-paint DOM against the
   pre-phase page must find only those two text changes.)
2. After at least one completed run, reloading shows `Your recent research (N)`
   as a collapsed `<details>` between the limits line and `#out`; N matches
   the caller's session count (≤10 rows rendered).
3. A different browser (different identity) does NOT see those sessions.
4. Clicking a row renders the stored conversation into `#out`, sets the
   follow-up target, and the next submission POSTs to
   `/sessions/{id}/ask/stream`.
5. Resuming an expired/foreign session shows the `That session has expired`
   error card, removes the row, and leaves the page usable for a fresh
   question.
6. `GET /sessions` failing, returning non-2xx, or returning `[]` renders no
   session UI and no error — the core ask flow is unaffected.
7. No new colors, fonts, font sizes, or weights: every new rule uses existing
   CSS custom properties; dark mode works with zero new `@media` rules.
   **Measured baseline (2026-08-05, current tree):** `font-size` values
   declared in `src/research_agent/static/index.html` are exactly
   {.78rem, .82rem, .85em, .88em, .9rem, .95rem, 1.15rem, 1.6rem} and
   `font-weight` values are exactly {600, 700}. The post-phase sets must be
   identical — this gate is falsifiable because adding any value changes a
   measured set, not a `>= 1` count.
8. All new DOM is built via `el()`/`textContent`; `grep -c innerHTML
   src/research_agent/static/index.html` is 0 (measured baseline on current
   tree: 0 — note the full path; CONTEXT's `static/index.html` shorthand does
   not exist at repo root).
9. The file remains self-contained: no external requests beyond the API
   endpoints; the Dockerfile still ships it as one COPY.
10. The limits line, when `/demo` is identity-aware, names both scopes: the
    per-browser rate limit AND the all-visitors spend figure.
11. Keyboard: session rows are focusable in DOM order, activate on
    Enter/Space (native `<button>` behaviour), and show the accent
    focus-visible outline.
