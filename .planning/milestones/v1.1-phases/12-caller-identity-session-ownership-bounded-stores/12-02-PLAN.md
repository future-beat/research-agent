<objective>
Give the demo an identity without a wall. A pure-ASGI middleware resolves the `ra_id` cookie or
mints a fresh signed one, sets `scope['state']['identity']` for every request, and appends
`Set-Cookie` on the way out ONLY when it minted — on every response shape the service produces
(JSON, `FileResponse`, `StreamingResponse` SSE). It is mint-on-response and NEVER 401: a
first-time caller's `POST /research/stream` must succeed AND carry the cookie in the SSE response
headers. Token is `v1.<uuid4hex>.<hmac-sha256>` via stdlib `hmac`; secret is
`IDENTITY_SIGNING_SECRET` (Fly secret), degrading to a per-process ephemeral secret when unset.

Purpose: this is the identity every later wave keys on (limits, session ownership, note scoping).
It must be invisible to a stranger following a résumé link — zero JS changes, no visible step.
Output: `identity.py`, middleware registration, and the test seam (`base_url="https://testserver"`
plus a public `mint()` helper) that all later waves reuse.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser cookie → server | the `ra_id` cookie is attacker-supplied on every request; verify before trust |
| server → browser | Set-Cookie attributes are the only thing stopping script/CSRF access to the token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02-01 | Spoofing | forged/tampered `ra_id` token | mitigate | HMAC-SHA256 over `v1.<id>`; `verify` uses `hmac.compare_digest`; any tamper → None → fresh mint (attacker gets a NEW empty identity, never another's) |
| T-12-02-02 | Information disclosure | token readable by script / timing attack | mitigate | `HttpOnly` removes it from `document.cookie`; `compare_digest` is constant-time; secret reported presence-not-value in /health (Wave 5) |
| T-12-02-03 | Tampering (CSRF) | ambient cookie on cross-site POST | mitigate | `SameSite=Lax` strips the cookie from cross-site POSTs; all mutations require a JSON body (cross-origin JSON POST triggers a preflight this service never approves — no CORS middleware); documented in ADR-0007 (Wave 5) |
| T-12-02-04 | Denial of Service | free-to-mint identities (Sybil) | accept | Locked design: per-identity limits are fairness only; the global spend cap (Wave 2) is the bill's backstop and is NEVER removed |
| T-12-02-05 | Elevation/Break | Secure cookie silently dropped in tests → identity re-minted every request | mitigate | `TestClient(base_url="https://testserver")`; `Secure` is unconditional (no prod/test fork in a security attribute) |
</threat_model>
