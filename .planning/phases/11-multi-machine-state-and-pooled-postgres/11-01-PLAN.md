<objective>
Replace the single lock-guarded Postgres connection in `db.py` with one process-wide
`psycopg_pool.ConnectionPool` per DSN, shared by all three stores.

Purpose: REQ-connection-pool. The reversal is justified by the machine count rising —
`fly.toml` sets `hard_limit = 16`, and two machines means **up to 32 in-flight requests
against one database**. Before this phase those 32 requests would have queued behind a single
serialised connection across a ~5 ms network hop instead of a local socket. That is the link
between the pool and the concurrency change, and it belongs in the module docstring verbatim.

Output: a pooled `db.py`, `psycopg-pool==3.3.1` pinned, and `tests/test_db.py` — a module that
does not exist today, even though `db.py` is the phase's main risk surface.

**No store needs editing.** `sessions.py`, `metrics.py` and `memory.py` each do
`self.db = database or db.Database(dsn)` and then `ensure_schema(...)`; none of them touch
`_conn` or `_lock`. The blast radius of this plan is one production module.
</objective>

  <action>
    Reimplement `Database.cursor()` on the pool. `psycopg_pool.PoolTimeout` and `PoolClosed` both
    **subclass `psycopg.OperationalError`** — verified in `psycopg_pool/errors.py`. The existing
    `except (OperationalError, InterfaceError)` arm would therefore catch a checkout timeout and
    retry it, doubling the worst-case wait on an unreachable database and pushing three `/health`
    probes from 6 s to 12 s. Catch `(PoolTimeout, PoolClosed)` **first** and re-raise immediately:
    the wait has already happened, and a second one buys nothing.

    Keep the two properties the current code has and the stores rely on: the retry is limited to
    exactly **one** attempt, and to connection errors only, so a genuine SQL error surfaces rather
    than running twice; and a non-database exception raised inside the `with` body — `KeyError` from
    `sessions.append_turn` is the live example — still propagates untouched.

    In `_apply_schema()`, wrap the DDL execution in a Postgres session-level advisory lock. Add a
    module constant `SCHEMA_LOCK_KEY = 3895545195` with a comment naming its origin
    (`zlib.crc32(b"research_agent.schema")`) — one key for all three schema blocks, so they
    serialise against each other too, not one key per store. Take it with
    `SELECT pg_advisory_lock(%s)` and release it in a `finally` with `SELECT pg_advisory_unlock(%s)`.
    Use the session-level pair, **not** `pg_advisory_xact_lock`: under `autocommit=True` there is no
    transaction to hang the lock on.

    Why this is needed now and was not before: `CREATE TABLE / INDEX / EXTENSION IF NOT EXISTS` is
    not atomic against a concurrent creator. This is the first phase in which two processes ever run
    the lazy schema path simultaneously against an *empty* database — which `fly deploy` across two
    machines and a start-clean database together guarantee. Belt and braces: treat
    `psycopg.errors.DuplicateTable`, `DuplicateObject` and `UniqueViolation` raised by the DDL block
    as "already applied" rather than as failure.

    `ensure_schema`'s contract does not change: it registers the SQL, tries once, and suppresses
    every exception. `_apply_schema` stays idempotent and retried on first use. **No DDL runs at
    construction time** — SC-4 stays true.

    Extend `tests/test_db.py`: against the unreachable DSN with `PG_CONNECT_TIMEOUT=1` and a small
    `PG_POOL_TIMEOUT`, assert that a `cursor()` call raises inside roughly one checkout timeout, not
    two — measure with `time.perf_counter()` and assert an upper bound below `2 ×` the configured
    timeout, so a reintroduced retry fails the test rather than merely slowing it. Assert
    `issubclass(PoolTimeout, psycopg.OperationalError)` explicitly, so the test documents *why* the
    exclusion exists and starts failing if psycopg ever changes it. Cover the retry-once path with a
    fake pool whose first `connection()` raises `OperationalError` and whose second succeeds, and
    assert a `ProgrammingError` is **not** retried. Name them so `-k pool_timeout_not_retried` and
    `-k reconnect` each select at least one.
  </action>

| app process → managed Postgres (cross-provider) | DSN, credentials and every statement cross the public internet |
