    Add four Postgres-gated tests to `tests/test_store_contract.py`. Every one uses the existing
    `@pytest.mark.skipif(not HAS_POSTGRES, ...)` idiom so it skips cleanly without `DATABASE_URL` and
    runs for real in CI. **Do not add a `conftest.py`** — this repo has none by convention; shared
    fakes live in the owning module and are resolved via `pythonpath = [".", "src", "tests"]`.

    1. **`concurrent_schema_init`** — construct two `Database` objects on the same DSN against a
       schema that has been dropped first, and drive `_apply_schema` from two threads started at the
       same barrier. Both must return without raising and both must end with `schema_applied` True.
       This is the two-machines-booting-against-an-empty-database race: `CREATE ... IF NOT EXISTS`
       is not atomic against a concurrent creator, and it was structurally impossible to hit before
       this phase because only one process ever ran the lazy schema path.

    2. **`pgvector_search_path`** — assert the pool's `configure` callback took effect: open a
       connection through a `Database` and read back `SHOW search_path`, asserting `extensions`
       appears in it. Then exercise an actual `%s::vector` cast through `PgVectorMemoryStore` on the
       contract table with the 5-dimensional `FakeEmbedder`, proving the cast resolves rather than
       merely that a setting is set. Supabase installs the extension into `extensions`; CI's image
       does not have that schema at all, and Postgres tolerates missing schemas in `search_path`, so
       the test must pass in both worlds.

    3. **`cross_instance` session resolution** — write a session through one `PostgresSessionStore`
       and read it back through a **separately constructed** `PostgresSessionStore` on the same DSN,
       asserting identical content. This is the actual mechanism SC-3 depends on. A second machine
       adds a network boundary and a Fly routing decision; it does not add a new code path. Say so in
       the docstring, and say what it does *not* prove — that the proxy routes to two machines, which
       is verified live in plan 11-05.

    4. **`concurrent`** — drive N threads (N comfortably above `PG_POOL_MAX_SIZE`, e.g. 12 against a
       max of 5) through `store.count()` simultaneously; assert every thread succeeds and none raises
       `PoolTimeout`. Before this phase all N would have queued behind one lock-guarded connection.

    These tests raise the local skip count. That is expected and legitimate — see the note in
    `<verification>`. What must never happen is a test that skips **under `REQUIRE_POSTGRES`**, which
    would undermine `test_postgres_really_ran_when_ci_said_it_would`.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `/health` response → the public internet | `/health` is unauthenticated and reports store locations |
| pool error → `_probe` → response body | Pool errors can echo conninfo, which carries a password |
| test suite → real Postgres in CI | Tests execute DDL and `pg_terminate_backend` against a shared CI server |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-06 | Information disclosure | `/health` `machine` key | accept | `FLY_MACHINE_ID` is a routing identifier already exposed by `fly-force-instance-id` and by Fly's own response headers; it is not a secret, and SC-3 is undemonstrable without it |
| T-11-07 | Information disclosure | `_probe` detail from a `PoolTimeout` | mitigate | `_redact()` already strips URL credentials; Task 1 adds an explicit assertion that the DSN password appears nowhere in the `/health` body |
| T-11-08 | Denial of service | `pg_terminate_backend` in the reconnect test | mitigate | Scope the kill to this test's own backends by `application_name`/`usename` and exclude `pg_backend_pid()`, so a shared CI server is not disrupted |
| T-11-09 | Tampering | new Postgres tests writing to shared tables | mitigate | Use the existing `CONTRACT_NOTES_TABLE` isolation idiom and the existing `TRUNCATE` fixtures; add no new unqualified table names |
</threat_model>
