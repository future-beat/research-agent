<decisions_this_plan_locks>
**P-05 — The policy is derived at runtime, not frozen as hash literals.** 19-CONTEXT and the
UI-SPEC both leave this to the planner "provided the drift-fails-a-test property holds either
way". Runtime derivation is chosen because the served header can then never disagree with the
page: the live demo cannot silently break. The rejected alternative — frozen hash literals
plus an equality test — reds on a benign CSS tweak, and a gate that cries wolf gets silenced
by whoever is updating the literal for the fourth time.

The drift property is carried instead by gates that red only when something genuinely changed
about what the policy must PERMIT: the derivation test (Task 2), which catches a
hand-maintained or wrongly-computed hash, and the structural counts (Task 2), which catch a
second inline block, a first inline handler and a first `style=` attribute — the three edits
that change the policy's shape rather than its digits.

**Consequence for 19-VALIDATION:** the byte-edit mutation that row prescribes cannot red under
P-05 — a byte edit moves both sides of a derivation together, correctly. It is replaced by two
mutations that do red and test the same property more directly: hand-maintaining one hash in
`csp.py`, and adding an inline handler to the page. Task 3 records this refinement in the
19-VALIDATION row itself, with the reason, rather than leaving a row whose mutation nobody can
run.

**P-06 — The header attaches to the `text/html` branch of `index()` and nowhere else.** The
UI-SPEC permits the JSON branch too. Narrower is chosen because "absent everywhere except one
response" is a testable claim, and its test is exactly the gate that catches a future
middleware attaching the header globally — which is the mechanism the UI-SPEC forbids, since
it is the one that could disturb the SSE responses' own headers.
</decisions_this_plan_locks>

  <action>
Create `src/research_agent/csp.py`, a pure module with no FastAPI import, so both the route and
its tests can use it without a running app.

It exposes:

1. `DIRECTIVES` — an ordered tuple of the seven directive strings from the UI-SPEC's contract,
   with `{script}` and `{style}` placeholders in the two `sha256-` slots. This tuple is the ONE
   place the directive set is written down; the route and every test read it from here. A
   module docstring records where each directive comes from and why the two absent-by-design
   families (`img-src`/`font-src`, and any `unsafe-` source) are absent — the page loads
   nothing external and has no inline handlers or style attributes to need them, so admitting
   either would be admitting a capability nothing asked for.
2. `inline_blocks(html) -> tuple[list[str], list[str]]` — returns (script bodies, style bodies)
   via two non-greedy `re.S` patterns over the bare tags. A plain regex is sufficient and is
   the right size for a file with exactly two attribute-free tags; the docstring says so and
   says what would change that (an attribute on either tag).
3. `sha256_source(text) -> str` — `base64.b64encode(hashlib.sha256(text.encode("utf-8")).digest()).decode()`.
   The bytes hashed are exactly the bytes between the tags, which is what a CSP element hash is
   defined over.
4. `policy(path) -> str` — reads the file, extracts the blocks, and returns the `"; "`-joined
   directive string. It raises with a message naming the counts if the file does not have
   exactly one of each: a policy carrying one hash for two blocks is a policy that is silently
   wrong, and failing loudly beats serving it. Cached with `functools.lru_cache` keyed on the
   path, so the file is read once per process — first request, never import time, which keeps
   DEC-18 intact. Tests that need a fresh read call `policy.cache_clear()`.

csp.policy(DEMO_PAGE)})`. Nothing else in `index()` changes; the JSON branch is untouched per
P-06. Add a short comment at the call site naming P-06: this is the only attachment point, and
a middleware would be the wrong mechanism because it would reach responses whose headers this
phase promised not to touch.

directive names present are exactly the seven from `csp.DIRECTIVES` in order, and assert the

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → `GET /` (text/html) | Anonymous browsers execute the page's inline script. The CSP is the browser-side integrity control over what that page may run and reach. |
| repository → shipped page | Whoever edits `static/index.html` changes what the policy must permit; the gates are the boundary control. |
| CSP mechanism → other responses | A broadly-scoped attachment mechanism could reach responses with existing header contracts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-06 | Tampering | injected inline script on the demo page | high | mitigate | `default-src 'none'` plus hash-only `script-src`. No `unsafe-inline`, no `unsafe-hashes`; Task 2 asserts their absence in the served string. An injected script has no matching hash and does not run. |
| T-19-07 | Information Disclosure | exfiltration from the demo page | medium | mitigate | `connect-src 'self'` and `form-action 'self'` confine every fetch and every form target to this origin; `base-uri 'none'` forbids injecting a `<base>` to relocate relative URLs. |
| T-19-08 | Spoofing | clickjacking the demo | low | mitigate | `frame-ancestors 'none'`. Free hardening, invisible to page behaviour; Task 1's directive-set assertion pins it. |
| T-19-09 | Tampering | policy drifting out of step with the page | high | mitigate | Runtime derivation (P-05) makes hash drift structurally impossible; the counts and handler gates (Task 2) catch the shape changes derivation cannot follow; `policy()` raises rather than serving a one-hash-for-two-blocks policy. |
| T-19-10 | Denial of Service | a broad attachment mechanism disturbing SSE headers | medium | mitigate | P-06 confines attachment to one call site; Task 3's absence test plus the middleware mutation enforce it, and the SSE caching headers are asserted explicitly. |
| T-19-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this plan; the module uses `re`, `hashlib`, `base64` and `functools` from the stdlib. 19-RESEARCH's Package Legitimacy Audit records N/A. |
</threat_model>
