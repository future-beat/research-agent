<objective>
`/health` reports whether the Anthropic and Voyage keys actually work, beside the presence
booleans it already reports, backed by a cached fire-and-forget probe that the liveness path
never waits on.

Purpose: the Phase 11 revoked-key outage — a container Fly called healthy while every run
failed upstream — becomes visible in `/health` within one probe TTL, WITHOUT reintroducing
the restart hazard the presence-only design exists to prevent.

Output: a credential cache and two provider probes in `service.py`, four new flat fields per
provider in `/health`'s credentials block, and a test group that pins every edge the design
turns on.
</objective>

<decisions_this_plan_locks>
These four were left to planner discretion by 19-CONTEXT's "Claude's Discretion" section and
by 19-RESEARCH's Open Questions. They are settled here; the executor implements them as
written and does not re-litigate them.

**P-01 — Field shape: flat keys, not a nested object.** `credentials.anthropic` is a `bool`
today. Turning it into `{present, valid, checked_at}` changes an existing field's TYPE, which
the additive-only constraint 19-CONTEXT inherits from Phase 12's rollout style ("no field
disappears") forbids. The block gains six new sibling keys instead:
`anthropic_valid`, `anthropic_checked_at`, `anthropic_error`, and the three `voyage_*` twins.
`identity_signing` is untouched.

**P-02 — TTL: a new `CREDENTIAL_PROBE_TTL`, default 300.0s, floor 30.0s.** It answers a
different question from `HEALTH_PROBE_BUDGET` ("how often do we attempt a probe at all" vs
"how long may one probe attempt take"), so it gets its own name and its own default, shaped
exactly like `health_probe_budget()` (`service.py:463-472`). The 30.0s floor is Fly's own
health-check interval (`docs/OPERATIONS.md:135-137`): below it, a mistuned env var would turn
`/health` into a per-request prober (19-RESEARCH Pitfall 4).

**P-03 — Executor: share `_probes()`.** 19-RESEARCH Open Question 2's recommendation. A
second pool is warranted only by observed store-probe contention, and there is none.

**P-04 — Voyage probe spend: EXCLUDED from cost accounting, stated in code.** 19-RESEARCH
Open Question 3's recommendation and Pattern 4's Option A: `report_embedding()` is a no-op
outside an open meter, so a probe that opens none is excluded by construction rather than by
special case. ATTRIBUTED has no existing sink — `record_embedding()` folds a meter into a
RUN's totals and a background probe has no run. The exclusion gets a comment at the probe AND
a test, per 19-CONTEXT: "deliberately, stated in code — not silently."

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → `GET /health` | `/health` is deliberately unauthenticated (`guard`'s docstring: ops reads stay open on purpose). Anything the credentials block prints is world-readable. |
| service process → Anthropic / Voyage | Outbound provider calls made on a background thread with the process's real API keys. |
| probe thread → request thread | The probe shares a process with in-flight paid runs and their cost accounting. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-01 | Information Disclosure | `/health` credentials block | high | mitigate | Validity is a tri-state boolean and a timestamp; the error field carries `type(exc).__name__` only. `str(exc)` is never stored or served (Task 1 step 4), and Task 2 pins it with a secret-shaped-token test. |
| T-19-02 | Denial of Service (self-inflicted) | Fly liveness check → `/health` | critical | mitigate | The refresh is `submit()`ed and never `.result()`ed; the read path returns the cache. Task 3's never-waits test plus Task 1's blocking mutation are the enforcement. `/ready` gains nothing (Task 3 test 5). |
| T-19-03 | Denial of Service | provider rate limits / spend | medium | mitigate | Presence gate before submission, one in-flight refresh per provider, and a 30s TTL floor (P-02) so probe volume tracks the TTL rather than request volume. Task 3 tests 1–3. |
| T-19-04 | Repudiation | cost accounting | medium | mitigate | Probe spend is EXCLUDED by construction (P-04) and the decision is stated in a comment AND pinned by a non-vacuous meter test, so a later refactor that silently attributes a probe to a visitor's bill fails a gate rather than a reconciliation. |
| T-19-05 | Tampering | executor thread starvation | low | accept | The credential refresh shares `_probes()`' three workers with store probes (P-03).
