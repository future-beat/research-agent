<domain>
## Phase Boundary

The classifier moves to `claude-opus-5` as a deliberate, recorded per-node model choice;
the four golden labels BOTH models dispute are resolved deliberately; and the six
`topic_type`-refused recordings from Phase 21 get one user-approved paid re-attempt under
the fixed classifier. Phase 22 (the close-out) runs after and records what survives.

**The measurement this phase rests on (2026-08-15, n=1 per case, $0.053):** over the 38
golden cases carrying an `expect_topic_type`, Opus 5 matched 34/38 vs Sonnet 5's 29/38 —
five fixes, zero regressions. Cost delta ≈ +$0.0005/run (~140 input tokens, ~5 output,
thinking disabled): ~0.2% of a measured $0.21–0.32 run. Probe rows archived at the
scratchpad's `classifier-probe.json` during the session; the phase RE-RUNS the probe
rather than trusting that file.

**Not in this phase:** the judge (stays `claude-opus-4-8` — ADR-0012's independence from
the critic is the entire point; the critic IS Opus 5, so a judge move here would undo
Phase 18); the writer/responder models; graders; REFUSAL_PATTERNS; the contested-case
pins (their record/replay divergence is recorded by Phase 22, fixed by a successor
milestone); any Limitations bullet (Phase 22's).

<decisions>
## Implementation Decisions

### The classifier runs Opus 5 — user-chosen model, do not second-guess

- The user chose `claude-opus-5` for the classifier. The choice is settled; the
  measurement confirmed it (and the orchestrator's initial skepticism was wrong —
  recorded in the ROADMAP entry). What remains open is the MECHANISM, which is
  Claude's discretion (below).

### The probe repeats before the switch is trusted — success criterion 2

- The 2026-08-15 probe was n=1 per case and classification is not pinned deterministic.
  Execution re-runs the two-model probe over all labelled cases (~$0.05) and the switch
  is trusted only if the shape holds (Opus ≥ Sonnet, zero regressions). If it does NOT
  hold, that is a checkpoint back to the user with the new numbers, not a silent
  proceed-anyway or a silent abort.

### The four both-models-disagree labels are resolved deliberately — criterion 3

- `general-defines-a-term`, `chatty-label-falls-back`, `followup-with-no-prior-research`,
  `injection-tries-to-force-approval` (per the 2026-08-15 probe; re-verify at execution):
  both models say `technical` where the golden case says `general`. Two models
  independently disagreeing with the dataset is evidence about the DATASET.
- Resolution options, in the researcher's order of preference to establish: correct the
  labels with reasoning recorded (but the `general` stratum must not be quietly gutted —
  if a case's job was to test the general path, relabeling it needs a replacement or an
  honest note that the stratum shrank); reword the task so the intended label becomes
  true; or document the divergence and leave the label. Whichever, `dataset.py` changes
  here are LABEL/TASK-level only — pins, notes, reports stay per the Phase 21 lesson.
- Note the tension with ADR-0012's fence as inherited by Phase 21 ("no grader/judge/
  dataset changes"): that fence protected Phase 21's record run from moving its own
  goalposts. This phase's explicit mandate is to resolve the labels — the fence is
  lifted HERE, for labels/tasks only, by the user-ratified requirement.

### The re-record is one checkpointed paid stage — criterion 4

- The six `topic_type`-refused cases (per `evals/REFUSALS.json` kinds/details; re-derive
  the exact list at execution — some refused on topic_type PLUS other graders and may
  refuse again for the other reason, which is fine and stays documented) get ONE
  re-attempt under the new classifier, behind a user-approved checkpoint with a fresh
  quote (~$2.40 at Phase 21's measured per-case actuals; re-quote at run time).
- Successes move from `REFUSALS.json` to `evals/fixtures/`; failures stay documented
  with updated reasons. The union gate (`test_every_golden_case_is_recorded_or_
  documented_as_refused`) must hold before AND after — its overlap arm is exactly the
  gate that catches a stale refusal record left behind after a successful re-record.
- Phase 21's discipline is inherited wholesale: `--case`-explicit invocation, P-06 env
  assertions before `--yes` (CRITIC_MODEL, EVAL_JUDGE_MODEL, VECTOR_STORE, DATABASE_URL
  — plus whatever new knob this phase adds, which must be asserted to its INTENDED
  value, not merely unset), refusals never auto-retried, report JSONs archived to the
  phase dir, actual-vs-quote in the SUMMARY.

### Claude's Discretion

- **The mechanism.** Env knob (`CLASSIFIER_MODEL`, the `CRITIC_MODEL` precedent) vs a
  code-level default change. THE TRAP the researcher must resolve: if the knob defaults
  to `MODEL` (sonnet) and only `fly.toml` pins Opus, then LOCAL record runs — including
  this phase's own re-record stage — classify with Sonnet and the re-record fails for
  the same reason it failed in Phase 21. Whatever the mechanism, production AND the
  recording path must both get Opus 5 by default, and the fixture's `models` metadata
  should record the classifier model so replay provenance stays honest (check what
  `write_fixture` records today and what `grade_fixture_current` compares).
- Whether this earns an ADR (a per-node model choice reversed a "one MODEL constant"
  position — the CRITIC_MODEL precedent got Phase 16 + ADR treatment; symmetric
  treatment is the default expectation, researcher confirms numbering vs Phase 22's
  planned 0013 and the renumber contingency already written into 22's plans).
- Probe implementation: a throwaway script vs a committed, keyless-skipped probe tool.
  (It cost $0.05 and needed a key — it cannot be a CI gate; but a committed script with
  a --yes-style guard would make the measurement repeatable. Planner's call.)

<specifics>
## Specific Ideas

- The probe comparison must hold same-prompt, same-parameters — the measurement's
  validity came from changing ONLY the model string. If the planner is tempted to also
  improve the classifier prompt, that is scope creep: one variable per phase.
- `budget-cap-is-labelled`-style offline cases script their classifier output — the
  offline suite never calls a model, so the model change is invisible to CI by design.
  Say so in the SUMMARY rather than letting a green suite imply the change was tested
  keylessly.
- Fixture metadata: if `models` gains a `classifier` field, older fixtures without it
  must keep replaying (additive-only, the Phase 12 payload convention).
