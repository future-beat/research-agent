### The trap, closed — traced on every path

The phase's central hazard was a `classifier_model()` defaulting to `MODEL`, which would leave
local record runs classifying on Sonnet while the deploy config claimed Opus. Traced
exhaustively rather than spot-checked:

| Path | How it reaches a classifier model string | Resolves to (nothing exported) |
|---|---|---|
| Production service | `service.py` → `graph.app` → `classifier_node` → `classifier_model()` | `claude-opus-5` |
| Local record path | `evals/harness.py:304,321` `graph.app.invoke(...)` → same node | `claude-opus-5` |
| REPL | `chat.py:58` `app.stream(state)` → same node | `claude-opus-5` |
| Probe | Deliberately **literals** (`claude-sonnet-5` / `claude-opus-5`), never the accessor | both, by name |
| Deploy config | `fly.toml:78` `CLASSIFIER_MODEL = 'claude-opus-5'` | agrees with the code default |

There is exactly one runtime resolution site in the repository. The probe's use of literals is
correct and load-bearing: reading the accessor there would make the report describe the
operator's shell rather than two named models, and two reports would not be comparable.

`{passed: 8, failed: 0}` on the very eight cases that refused on that grader in Phase 21 — the
recording path demonstrably got Opus, on the operator's own machine, with nothing exported.
