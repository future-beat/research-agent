20-CONTEXT's "Claude's Discretion" section and 20-RESEARCH's Assumptions Log left five
things open. They are settled here; the executor implements them as written and does not
re-litigate them.

**P-01 — Knob name and clamp: `NOTE_CAP_PER_OWNER`, default 100, the
`cost_discount_factor()` clamp direction.** Unparseable OR <= 0 falls back to the default
— NOT `note_ttl_seconds()`'s floor-at-zero (where 0 is a meaningful value the TTL tests
deliberately use) and NOT `DEMO_RATE_LIMIT_PER_HOUR`'s "0 disables" convention. A literal
cap of zero makes every `add()` evict the note it just wrote: memory recall silently
disabled with no error and no log line, the same shape of foot-gun `COST_DISCOUNT_FACTOR=0`
was (usage.py:236-251 states the argument; 20-RESEARCH Pattern 1 adapts it). An operator
who wants no cap does not set the variable. This settles 20-RESEARCH Assumption A2.

**P-02 — Eviction lives per-backend inside each `add()`, no shared helper.** The four
storage shapes (Python list x2, chroma metadata+ids, SQL rows) have no common "oldest"
representation; a shared helper would be an if/elif dispatcher with no real reuse
(20-RESEARCH Don't Hand-Roll). Per-backend code, one shared behavioural suite as referee —
the existing shape of this file for the TTL sweep and owner scoping.

**P-03 — Ordering: sweep (TTL, unconditional) -> insert -> evict; the cap counts only
post-sweep survivors.** This is the one ordering that preserves the existing `test_note_ttl`
guarantee that `add()` physically removes expired rows even for owners nowhere near the
cap. 20-RESEARCH Pitfall 2 gives the failure scenario; Task 2's composition case pins it.

**P-04 — `add()` returns nothing about eviction.** No caller needs it, the seam shape is
frozen by DEC-08, and a trace entry would widen a return type three of four callers ignore.

**P-05 — Tie-break is storage-native insertion order everywhere; `created_at` is never the
sole key.** json/memory get it free from list order (entries only ever grow by append);
pgvector from `BIGSERIAL id`; chroma gains an explicit integer `seq` metadata field,
computed in `_sweep()` as max-over-survivors + 1 — a completeness scan, which does not
depend on `get()`'s undocumented return order (20-RESEARCH Pattern 3, Assumption A3).
Legacy chroma rows without `seq` read as 0: they are genuinely the oldest, and the 7-day
TTL retires them. This matters empirically, not theoretically: `time.time()` measured 14
unique values across 200 calls on this machine, so the obvious eviction test WILL collide.

**P-06 — The chroma-specific ordering gate lives in `tests/test_store_contract.py`, not
`tests/test_memory_stores.py`.** 20-RESEARCH suggested either; the contract file is where
`ChromaMemoryStore` is already imported, guard-skipped and constructed at a tmp_path
(fixture at test_store_contract.py:108-118), and where the backend-specific pgvector tests
already live. test_memory_stores.py has no chroma plumbing and gains none.
