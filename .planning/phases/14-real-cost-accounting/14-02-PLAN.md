<objective>
Capture the Voyage token count the wrapper currently receives and discards, fold per-run
embedding cost into usage accounting through a contextvar meter, and migrate the runs table
in both backends so the new RunRecord fields cannot crash `asdict()` INSERTs on live
tables. Close with the end-to-end behavioural gate: settled spend is multiplied cost,
applied exactly once.

Purpose: SC-5's accounting half ("approximates the invoice" is false while a whole provider
is missing — the Phase 13 debt lands here) and SC-4's Voyage arm. The schema migration is
the phase's main construction risk (RESEARCH Pitfall 1): a missed column 500s every run at
the metrics step on the first post-deploy request.

Output: meter + record_embedding in usage.py; reporting seam in memory.py; fold in
graph.py; migrated RunRecord/schemas in metrics.py; the settle-sees-multiplied-cost
integration gate.
</objective>
