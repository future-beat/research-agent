<objective>
Give sessions an owner and an expiry, and turn `SESSIONS_TOKEN` from the visitor's credential into
the operator's. Sessions carry the minting identity; `GET /sessions` becomes caller-scoped, with a
valid operator token switching to the unscoped debugging view (dual-mode). Foreign and expired
sessions return **404 byte-identical to missing** (`No session {id!r}.`) — never 403, which would be
an existence oracle on ids that appear in shared URLs (continuing 10.5's leak-least posture).
Expiry is derived from `updated_at` (7 days, `SESSION_TTL_DAYS`): a lazy filter against the
database's own clock makes both machines agree, and an opportunistic sweep on `create()` bounds the
table. Reads never renew `updated_at`. The route-dependency surgery renames
`require_sessions_token` → `require_session_access` and EXTENDS the 10.5 walker test rather than
bypassing it. The two orphaned sessions (owner='') resolve for nobody and age out on their own.

This plan also corrects one stale rationale in the walker suite: after 12-03 moves the daily cap out
of `guard` and into the in-handler `reserve_or_429`, the preserved "no session route carries
check_daily_cap" assertion's comment (`tests/test_service.py` ~L606, which claimed `guard` "bundles
check_daily_cap") becomes false and the assertion trivially true. The structural assertion STAYS
(it still guards against a future refactor reaching for `guard` on a read); only its stated rationale
is corrected to point at where the real read-still-works guarantee now lives — 12-03's `reserve_or_429`
and its "reads survive the cap" behavioural test.

Output: owner+expiry in sessions.py, the dual-mode access dependency and owner-checked `_require` in
service.py, the extended structural walker, and the corrected cap-rationale comment.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller identity → session data | a session belongs to one identity; another must not read/delete/resume it |
| operator token → all sessions | the debugging view crosses the ownership boundary intentionally, fail-closed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-12-04-01 | Information disclosure | existence oracle on session ids | mitigate | 404 byte-identical for missing/foreign/expired at the single `_require` choke point; gate asserts equal detail strings |
| T-12-04-02 | Elevation of Privilege | reading/deleting another caller's session | mitigate | owner check in `_require`; ask routes enforce ownership in-handler; DELETE is owner-or-operator only |
| T-12-04-03 | Spoofing | operator view reachable without the credential | mitigate | operator path is the fail-closed `sessions_token()` match; unset token closes only the operator view (documented inversion) |
| T-12-04-04 | Tampering (regression) | a new session route ships with no auth (the 10.5 defect) | mitigate | structural router membership + extended walker (>=6 objects, every route carries require_session_access) |
