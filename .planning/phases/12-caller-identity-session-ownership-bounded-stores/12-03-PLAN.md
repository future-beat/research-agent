<objective>
Move rate-limit and spend-cap state out of per-machine memory (wrong twice on two machines) and
into Postgres, keyed on identity. Rate limit keys on `request.state.identity`, so fairness no
longer rides on `TRUST_FORWARDED_FOR` (which becomes vestigial — kept only for `client_ip` logging).
The daily cap gains reservations: an in-flight run reserves `DEMO_RESERVED_RUN_USD` ($0.20 default,
tunable) against the cap, checked-and-inserted inside a transaction holding
`pg_advisory_xact_lock(CAP_LOCK_KEY)` so concurrent guards cannot both pass (closing the ~3x
overshoot). The reservation settles to real cost when the run finishes — on BOTH the success and the
SSE-error arm — with a 900s staleness cutoff backstopping a crashed run. The global cap survives as
the backstop the whole identity design depends on: identities are free to mint, so the cap bounds
the invoice. The 429's "Read-only endpoints still work." contract survives verbatim, and `guard`
stays off the session reads.

Output: a `LimitsStore` seam (memory/postgres), identity-keyed enforcement, reserve/settle wiring.
</objective>
