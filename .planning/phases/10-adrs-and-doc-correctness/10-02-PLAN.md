    Title: `# ADR-0006 — Session endpoints use a separate, fail-closed SESSIONS_TOKEN`.
    `**Status:** Accepted`.
    **This record is NOT promoted from `docs/DESIGN.md`** — unlike 0001–0005 it originates in
    Phase 10.5, so use `**Source:** Phase 10.5 (2026-08-04), shipped as Fly release v4` in
    place of a `Promoted from:` line. Do not invent a DESIGN.md passage for it.

    Context: four session routes — `GET /sessions`, `GET /sessions/{id}`,
    `GET /sessions/{id}/trace`, `DELETE /sessions/{id}` — shipped with no credential at all,
    and the exposure was confirmed against production, not inferred: an unauthenticated
    `GET /sessions` returned real session contents and two `DELETE` calls returned 204 from
    the open internet. Setting `DEMO_TOKEN` did not close it, because `check_token` runs only
    inside `guard` and those four paths never reached `guard`.

    Decision, four parts, each with its reason:
    1. A separate `SESSIONS_TOKEN` (sent as `x-demo-token`), with `DEMO_TOKEN` accepted as a
       fallback *value*.
    2. It **fails closed** — 403 when unset — deliberately diverging from `check_token`'s
       open-when-unset convention, because the defect being fixed was a control that existed
       in code and went inert on a missing env var.
    3. `guard` is **not** applied to the reads: it bundles `check_token` + `check_rate_limit`
       + `check_daily_cap` indivisibly, so guarding reads would meter them against the
       caller's research quota and 429 them at the daily cap — contradicting the cap's own
       message that read-only endpoints still work. `check_rate_limit` is on the `DELETE`
       only.
    4. The four routes are grouped on an `APIRouter` rather than given four per-route
       dependency lists, so membership is structural — the original defect was four routes
       each independently forgetting a credential.

    Consequences — the first is the one this record exists for, so state it unmissably:
    **`DEMO_TOKEN` must never be set in production.** `guard` fronts `POST /research/stream`
    and the demo page sends no token header, so setting it 401s every anonymous visitor and
    takes the public demo offline. Any future refactor that "tidies" the two tokens into one
    reintroduces exactly that. Also: fail-closed cost ~14 test call-site updates; the token
    proves *authorised*, not *who*, so `GET /sessions` still lists every session to any token
    holder.

    Name **Phase 12** (REQ-store-lifecycle-and-ownership) in Consequences as the expected
    superseder — when per-caller identity lands, parts 1 and 2 are likely to be revisited —
    but leave Status `Accepted`. Do not write `Superseded` today.

    Use the three Nygard headings `## Context`, `## Decision`, `## Consequences`, matching
    0001–0005. Add it to the `docs/adr/` index created in plan 10-01, marked as originating
    in Phase 10.5 rather than promoted from DESIGN.md.
