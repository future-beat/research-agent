# Phase 22.5 Plan 01: The demo shows progress Summary

**One-liner:** `_stream` stops discarding the supervisor's chunk and forwards its `next_step` as an additive `{"node": <target>, "status": "started"}` event, so the researcher's row appears at the routing hop — milliseconds after the classifier finishes — instead of 120 seconds later at its own completion; the page draws that as a muted pending row and upgrades it in place, behind five new keyless gates and eight observed mutations.

**Zero spend.** Every command ran with `ANTHROPIC_API_KEY="" VOYAGE_API_KEY=""` explicitly prefixed. No deploy, no paid run, no `--live`.

## The headline gate was red on today's code

This is the one result that mattered, and the one that would have stopped the phase.

The plan's headline mutation — "restore the `continue` that discards the supervisor chunk" — **is** today's code, so the honest way to observe it red was to write the gate and run it against a wholly unmodified tree. Verbatim:

```
>       assert len(researcher) == 2, "expected one started and one completed researcher event"
E       AssertionError: expected one started and one completed researcher event
E       assert 1 == 2
E        +  where 1 = len([(1, {'node': 'researcher', 'recalled_from_memory': 0})])

tests/test_service.py:1150: AssertionError
```

One researcher event on today's wire, at index 1, carrying only its post-hoc detail. That single line is the defect the reproduction measured, in test form: the page cannot draw "searching the web" until the searching has already finished.

After the four-line `_stream` branch it is green. Re-applying the mutation afterwards reds it again on the same assertion with the same `1 == 2`. **Observed red twice, green once, exactly as the validation record demanded.**

## The five mutations of Task 1

| # | Mutation | Observed |
|---|---|---|
| a | restore the bare `continue` | **RED** on `assert 1 == 2` — pre-fix (test-first) and again post-fix |
| b | spread `_node_detail(routed_to, node_state)` into the started payload | **RED**: `Extra items in the left set: 'recalled_from_memory'` |
| c | rename the emitted status to `beginning`, page untouched | **RED**: `assert {'beginning'} == {'started'}` |
| d | move the new JS into a second `<script>` block | **RED** `assert 2 == 1` **and** `policy()` raised `ValueError` |

**Mutation (b) is P-02's argument made visible.** The leaked field is not merely extra, it is *fabricated*: at routing time `state["trace"][-1]` is the supervisor's own decision dict, which has no `recalled_from_memory` key, so `.get(..., 0)` returns the default and the researcher's started event would announce "recalled 0 notes" about work that has not happened. Every field `_node_detail` returns is post-execution; this is what reading one early actually produces.

**Mutation (d), both halves.** The block-count gate reds, and independently `csp.policy()` raises `ValueError: ... has 2 inline script block(s) and 1 inline style block(s)` — so `GET /` would 500 rather than serve a policy missing a hash. That loud failure is the design working: a half-hashed policy would leave the page dead in every browser while the server looked fine.

**Mutation (c), recorded precisely.** It reds on the vocabulary assertion (`statuses == {"started"}`), which runs before the page-source assertion. The page-source half was confirmed separately rather than assumed: `index.html` contains `"started"` once and `"beginning"` zero times, so both halves would red. Worth stating plainly so nobody later mistakes the gate for one that only checks the server.

The revision-loop test exists because that failure mode is invisible to the happy path.

## The protected tests, proven byte-identical

Both survive at zero edits, which is this phase's evidence that the change is *additive to* Phase 19's contract rather than a renegotiation of it:

```
test_stream_does_not_emit_supervisor_hops UNEDITED (524 bytes, sha equal)
test_stream_carries_node_detail UNEDITED (360 bytes, sha equal)
```

Extracted from `git merge-base HEAD main` (`b3c3fce`) and compared byte-for-byte. **Deliberately not `git diff | grep '^@@'`**: git's hunk-header function context names the `def` preceding the hunk, so it reports the *enclosing* function rather than which bytes changed — an unreliable proxy for "these bytes are unchanged" no matter where the edits land. (Checker W5 already corrected the plan's stated reason: the original text predicted a specific false-flag that measurement disproved. The method choice stands on the general argument, not the predicted one.)

The reason they hold is a single design fact: the started payload's `node` field is the **routed-to target**, never the literal `supervisor`. So `all(payload["node"] != "supervisor")` stays true, and the first test's docstring — "the supervisor still appears in the final trace, where it belongs" — stays literally accurate. Had either needed an edit, the design had drifted and the instruction was to stop.
