## What the reproduction established — measured, not inferred

One run against production, 2026-08-16, $0.2235, question "What is a vector database?":

| event | arrived |
|---|---|
| `classifier` (→ `general`) | **+2s** |
| `researcher` | **+122s** |
| `writer` | +132s |
| `critic` rejected | +143s |
| `writer` rev 1 | +155s |
| `critic` rejected | +167s |
| `writer` rev 2 | +178s |
| `critic` approved, then `result` | +183s |

**Everything worked.** The terminal `result` arrived, the run recorded (`runs_recorded`
13 → 14, sessions 7 → 8), it was billed $0.2235, and the connection was never dropped.
Three hypotheses died on this evidence: a Fly proxy idle timeout (the stream was alive at
+122s), a broken stream (it delivered every event), and the v21 classifier change (the
owner confirmed the symptom predates it by days, and the classifier answered in 2s).

**The defect is 120 seconds of silence at the front**, and its location matters more than
its length: it lands exactly where a first-time visitor decides whether the demo works.
After the researcher, events arrive every 5–12s and the page looks alive.

**Why the page cannot cover it today.** `index.html` creates a stage row only when a
`node` completion event arrives, so its last drawn label stays "classifying the topic".
It has an explicit branch for a dropped connection ("The connection dropped mid-run") —
the owner never saw it, which is itself evidence the connection stayed healthy.

### The fix is data already on the wire, one line from being used

`_stream` (`service.py:~395`) skips the supervisor's chunk:

    if node_name == "supervisor":
        continue  # fires between every node; pure noise on the wire

The supervisor's state carries `routed_to` — the name of the node about to run. The
reproduction's own trace shows `{"node": "supervisor", "routed_to": "researcher"}` firing
at ~+2s, two minutes before the researcher's completion. That comment was correct when
only completions mattered; it is now backwards, because `routed_to` is the ONLY signal of
what is starting. No heartbeat timer, no new plumbing, no polling.

### Claude's Discretion (researcher first, then planner)

- **Event shape.** A new event name (`stage`/`routing`) vs reusing `node` with a status
  field. Whichever, the client must never orphan or duplicate a row, and Phase 19's
  "exactly one terminal event" property must remain literally true — a starting event is
  not terminal and must not be counted as one.
- **Which routings to forward.** `routed_to: "done"` should presumably not draw a stage;
  and the supervisor fires between EVERY node, so a naive forward doubles the wire volume.
  Decide what the page needs versus what it can infer.
- **Client rendering.** A pending row upgraded in place on completion, versus a single
  "current stage" line. Whatever keeps the finished transcript readable — the pipeline
  being visible is the demo's whole point (`index.html`'s own header comment).
- Whether this earns an ADR (probably not — it fixes a defect rather than reversing a
  position — but the researcher should check whether any record claims completion-only
  streaming was deliberate).

</decisions>

## Specific Ideas

- The acceptance test a visitor would run: submit a question and see a *changing* label
  within seconds. Criterion 4 asks for that gap to be measured, not asserted — the
  keyless suite can prove the event is emitted on routing, and a post-deploy observation

  opposite. That framing belongs in the SUMMARY.

  suite proved the stream's contract and never asked whether a human would wait.
